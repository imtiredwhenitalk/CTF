# Operation Titan 🛡️

CTF-інфраструктура: CTFd + 11 завдань + OpenVPN з порталом для видачі `.ovpn`.

## Запуск

```bash
chmod +x setup.sh
./setup.sh --reset      # перший запуск / повний перезапуск з нуля
./setup.sh              # звичайний запуск (дані CTFd і VPN зберігаються)
```

Адресу сервера задано в `.env`: `PUBLIC_IP=10.10.15.124` (інтерфейс `ens18`). Вона потрапляє в `.ovpn` та в описи завдань CTFd.
Інша адреса: змініть `.env` або `PUBLIC_IP=x.x.x.x ./setup.sh`. Якщо PKI вже створено, адреса в профілях оновиться без `--reset`.
Адреса на сервері видана по DHCP (`dynamic`), тож зробіть резервування на роутері, інакше після зміни IP посилання перестануть працювати.

Після старту (CTFd налаштовується сам приблизно за хвилину; прогрес: `docker compose logs -f ctfd_setup`):

| Сервіс | Адреса |
|---|---|
| CTFd | http://10.10.15.124:8000 (`admin` / `admin`, пароль: `ADMIN_PASSWORD=... ./setup.sh --reset`) |
| VPN-портал | http://10.10.15.124:5050 |
| Завдання (напряму) | `http://10.10.15.124:8001` … `:8011` |
| Завдання (через VPN) | `172.28.0.11` … `172.28.0.21` (завдання 3, 8, 9, 11 — порт 80, решта — 5000) |

Якщо підмережа `172.28.0.0/24` збігається з вашою — змініть її у `docker-compose.yml`, `setup.sh` і `ctfd-setup/setup_ctfd.py`.

Якщо автоналаштування CTFd впало або завдання не з'явилися — подивіться `docker compose logs ctfd_setup` і повторіть:

```bash
docker compose up -d --force-recreate ctfd_setup
```

Скрипт ідемпотентний, тому повторний запуск оновлює наявні завдання й не створює дублікатів.

## Дизайн і завдання 1

- Усі сайти завдань і VPN-портал мають єдиний офлайн-дизайн (`shared/titan.css`, `shared/titan_ui.py`); Bootstrap із CDN більше не потрібен, тож усе працює без інтернету. Після зміни дизайну виконайте `tools/sync_ui.sh` (його ж викликає `setup.sh`).
- **01 SSTI Comms Console** — завдання повністю замінено (раніше тут був Git Leak & XOR). Flask-консоль підставляє позивний оператора в `render_template_string`, що дає Server-Side Template Injection і читання `/flag.txt`. Розв'язок: `writeups/01_ssti.md`.
- **06 AES ECB Oracle** — завдання перероблено повністю, бо старий варіант розв'язувався одним запитом до `/source`. Тепер це AES-ECB oracle із випадковим префіксом (0–15 байт, фіксований для процесу) і секретним токеном сховища, який генерується під час старту. Токен треба відновити byte-at-a-time атакою, після чого відкрити сховище через `/unlock`. Прапора в коді немає — він лежить у `/flag.txt`. Розв'язок: `writeups/06_ecb.md`.

## Що виправлено

- **CTFd auto-setup** — `setup_ctfd.py` переписаний: коректний nonce для форми setup і логіну, `CSRF-Token` для API, повтори запитів, PATCH для оновлення наявних завдань і прапорів. Старе завдання «01. Git Leak & XOR» автоматично видаляється, тому заміна завдання не залишає дублікатів у вже розгорнутому CTFd. Після створення скрипт перечитує завдання та прапори й завершується з помилкою, якщо чогось не вистачає.
- **Чому не було завдань** — перевірка адміна використовувала поле `type` з `/api/v1/users/me`, а CTFd його більше не повертає. Логін насправді проходив, але скрипт вважав його невдалим і виходив до створення завдань. Тепер адмін-доступ перевіряється через сторінку `/admin/challenges`.
- **CTFd оновлено до `3.8.9`** (остання стабільна версія) і зафіксовано в `docker-compose.yml`, щоб `latest` не ламав API несподівано.
- **docker-compose** — healthcheck-и (CTFd більше не стартує раніше за БД), прибрано застарілі `version`/`ULOGS`/`user: root`, фіксована мережа для VPN, завдання 01 переведено на Flask (порт 5000). `setup.sh` запускає `up --remove-orphans`, щоб старий контейнер `flag1_git` не займав порт 8001 після заміни завдання.
- **VPN** — `-n 10.8.0.0/24` у `ovpn_genconfig` був DNS-параметром, а не підмережею; тепер правильний `-s`, пушиться маршрут до мережі завдань, а не весь трафік. Портал працює без docker CLI (Python SDK), має головну сторінку (раніше `/` давав 404), перевірка сертифіката точна (раніше `grep` міг збігтися з іншим ім'ям).
- **setup.sh** — більше не знищує дані при кожному запуску (тільки `--reset`), коректні лапки, підтримка `docker-compose`/`sudo`.
- **02 JWT** — сучасний PyJWT забороняє PEM-ключ як HMAC-секрет, завдання було нерозв'язне; HS256 перевіряється вручну (вразливість збережена).
- **03 LFSR** — `flag.enc` не розшифровувався; перегенеровано (бінарний файл, seed 16 біт).
- **07 SQLi** — WAF блокував підрядок `or`, який є в слові `password`, тож колонку було не можна згадати; тепер блокуються лише окремі слова `union/or/and`.
- **08 Wiener** — флаг (264 біти) не вміщався в N (260 біт); згенеровано нову пару з N 1024 біт і малим `d`.
- **09 Stego** — `secret.txt` і `server.py` були доступні напряму (`/secret.txt`); тепер віддається лише `public/image.png`, це справжній PNG із ZIP у кінці.
